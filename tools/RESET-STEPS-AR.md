# تصفير بيانات نظام الأصيل — خطوات التنفيذ على لابتوب الفندق

> الهدف: تصفير الوحدات المالية والإدارية المطلوبة مع الإبقاء على التشغيل قائماً
> (الغرف، النزلاء، الحجوزات الحالية، المخزون، الموظفين، الإعدادات).

---

## 1. ما الذي سيحدث بالضبط

### يبقى كما هو (لن يُمس)

| الوحدة | ما يبقى |
|---|---|
| لوحة التحكم | تُحسب لحظياً من الغرف والحجوزات القائمة — تظهر صحيحة تلقائياً |
| شبكة الغرف | كل الغرف وأرقامها وأنواعها وأسعارها وحالاتها وعُهدتها |
| بيانات النزلاء الرسمية | كل ملفات النزلاء (الاسم، الرقم القومي/الجواز، الهاتف) + التقييمات |
| الحجوزات الحالية | كل حجز داخل الفندق أو قادم، بفواتيره المفتوحة |
| تدبير منزلي | حالات النظافة وبيانات الوحدة |
| الصيانة | التذاكر المفتوحة وقيد التنفيذ |
| المخزون والمستودع | مخزون الغرف والمواقع، الأذون، سجل التالف، حدود التنبيه |
| المقهى | الفئات والأصناف والأسعار والطاولات |
| المغسلة | فئات الأسعار |
| الموظفون والرواتب | الموظفون، سجلات الرواتب، الاعتمادات، الورديات |
| الإعدادات | بيانات الفندق، الشعار، الثيم، المستخدمون وكلمات المرور، كود الاسترجاع |

### يُصفَّر (يعود إلى صفر)

| الوحدة | المفتاح في ملف البيانات |
|---|---|
| الحسابات — دفتر الأستاذ | `ledgerEntries` |
| الحسابات — سجل تصحيح الفواتير | `folioAudit` |
| التدقيق الليلي | `nightAuditRuns` + إعادة `operationalDate` ليوم التنفيذ |
| المصروفات | `expenses` (وما يماثله في إصدارك) |
| الشركات | `companies` |
| التحليلات | `analytics*` |
| التسعير الديناميكي | `dynamicPricing` / `pricingRules` |

### ويُمسح معها — السجلات المالية القديمة

| السجل | لماذا |
|---|---|
| أرشيف أوردرات المقهى | مصدر إيراد يرحّله التدقيق الليلي |
| معاملات المغسلة | نفس السبب |
| الحجوزات المغادرة والملغاة | فواتيرها هي مصدر إيراد الغرف |
| تذاكر الصيانة المقفولة (resolved) | تكلفتها تُرحَّل كمصروف |

**السبب الفني:** التدقيق الليلي يمنع تكرار القيد بمقارنته بدفتر الأستاذ نفسه
(`src/js/accounting.js:227`). فلو مسحنا الدفتر وتركنا السجلات القديمة، أول تشغيل
للتدقيق الليلي بعد التصفير سيعيد ترحيل كل إيرادات الماضي وينقض التصفير.

---

## 2. قبل ما تبدأ

- **أغلق التطبيق تماماً.** النافذة المفتوحة تحتفظ بنسخة من البيانات في الذاكرة
  وتعيد حفظها فوق أي تعديل، فيضيع التصفير. تأكد من إنهائه في مدير المهام
  (Ctrl+Shift+Esc) — لا يوجد أي عملية باسم Alaseel.
- **انسخ مجلد `tools` كله إلى سطح المكتب** (الملفان `reset-system.cmd` و `reset-system.js`
  لازم يكونا بجوار بعض).
- الأداة تعمل بـ Node.js إن كان مثبتاً، وإلا تستخدم نواة Node المدمجة داخل تطبيق
  الأصيل نفسه — بدون تثبيت أي شيء.

## 3. الخطوات

### خطوة 0 — نسخة احتياطية يدوية (طبقة أمان إضافية)

1. اضغط `Win + R` واكتب `%APPDATA%` ثم Enter.
2. ابحث عن مجلد التطبيق (اسمه `alaseel-pms` أو `Alaseel PMS`) وبداخله `alaseel-data.json`.
3. انسخ المجلد كله والصقه على سطح المكتب باسم `AppData-قبل-التصفير`.

> الأداة تعمل نسخة احتياطية تلقائية أيضاً، لكن نسخة يدوية بعيدة عن المجلد أأمن.

### خطوة 1 — افتح موجه الأوامر في مجلد الأداة

افتح مجلد `tools` على سطح المكتب، اكتب في شريط العنوان `cmd` ثم Enter.

### خطوة 2 — جرد (قراءة فقط، لا يعدّل أي شيء)

```
reset-system.cmd report
```

يعرض: مسار ملف البيانات، وكل مفاتيح النظام وعدد سجلاتها، وما سيُمسح بالضبط.

> **مهم:** لو ظهر قسم **«مفاتيح اسمها يوحي بأنها تخص وحدة مطلوب مسحها، لكنها غير
> معروفة للأداة»** — دي مفاتيح إصدارك الأحدث. صوّر الشاشة وابعتها، أو أضِفها بنفسك
> في خطوة التنفيذ هكذا: `--also اسم1,اسم2`

### خطوة 3 — معاينة التصفير (لا يزال بدون كتابة)

```
reset-system.cmd apply --dry-run
```

راجع جدول «قبل / بعد» وقائمة «تم الإبقاء عليه». لا تكمل إلا لو الأرقام منطقية.

### خطوة 4 — التنفيذ

```
reset-system.cmd apply --yes
```

الأداة: تتأكد أن التطبيق مغلق ← تعمل نسخة احتياطية `alaseel-data.backup-<التاريخ>.json`
وتتحقق من سلامتها ← تكتب الملف الجديد كتابة ذرّية.

لو عندك مفاتيح إضافية من خطوة 2:

```
reset-system.cmd apply --yes --also اسم1,اسم2
```

### خطوة 5 — افتح التطبيق وتحقق بعينك

- **الحسابات:** الإيراد والمصروف وصافي الربح = صفر، دفتر الأستاذ فارغ.
- **التدقيق الليلي:** لا يوجد سجل تشغيل، واليوم التشغيلي = تاريخ اليوم.
- **الشركات / المصروفات / التحليلات / التسعير الديناميكي:** فارغة.
- **الغرف والنزلاء والحجوزات الحالية والمقهى والمغسلة والمخزون والموظفين:** كما هي.
- سجّل الدخول بنفس اسم المستخدم وكلمة السر القديمة (لم تتغير).

### خطوة 6 — تحقق نهائي

أغلق التطبيق، ثم:

```
reset-system.cmd verify
```

المفروض تظهر كل السطور `✓ صفر`. لو ظهر `✗ عاد!` فمعناه أن التطبيق كان مفتوحاً وقت
التنفيذ — أعد الخطوات 4 و 5 بعد التأكد من إغلاقه.

---

## 4. التراجع (لو حصل أي شيء غير متوقع)

1. أغلق التطبيق.
2. `Win + R` ← `%APPDATA%` ← ادخل مجلد التطبيق.
3. احذف `alaseel-data.json`.
4. أعِد تسمية `alaseel-data.backup-<التاريخ>.json` إلى `alaseel-data.json`.
5. افتح التطبيق — كل شيء رجع كما كان.

---

## 5. أوامر الأداة

| الأمر | الوظيفة |
|---|---|
| `reset-system.cmd auto --yes` | كل شيء بأمر واحد: بحث ← جرد ← نسخة احتياطية ← تنفيذ ← تحقق |
| `reset-system.cmd find` | البحث عن ملف البيانات بالمحتوى لا بالاسم (يدعم `--wide` و `--root`) |
| `reset-system.cmd report` | جرد للقراءة فقط |
| `reset-system.cmd apply --dry-run` | معاينة بدون كتابة |
| `reset-system.cmd apply --yes` | تنفيذ التصفير مع نسخة احتياطية |
| `reset-system.cmd verify` | تأكيد أن التصفير صمد |
| `--file "<مسار>"` | تحديد ملف البيانات يدوياً |
| `--also اسم1,اسم2` | مسح مفاتيح إضافية (تدعم `coffeeShop.orderHistory`) |
| `--keep-history` | الإبقاء على السجلات التشغيلية القديمة (غير موصى به — يُبطل التصفير) |
| `--force` | تخطّي فحص «التطبيق مفتوح» |

## 6. ملاحظات مهمة

- **كلمات المرور وكود الاسترجاع لا تتأثر** — `users` و `auth` محميان داخل الأداة ولا
  يمكن مسحهما حتى بـ `--also`.
- **الرواتب باقية** كما طلبت، رغم أنها بند مصروفات؛ لو أردت تصفيرها لاحقاً:
  `--also payrollRecords,payrollApprovals`.
- **الشركات ستُمسح**، فأي أوردر قديم كان مُحمَّلاً على شركة لن يجد اسمها — لا يؤثر على
  التشغيل، وكل الأوردرات القديمة ستُمسح على أي حال.
- الأداة تتعامل مع ملف البيانات الأحدث تعديلاً لو وُجد أكثر من ملف، وتطبع مسار الملف
  الذي اختارته قبل أي تعديل.
- **لو ملف البيانات خارج مجلد التطبيق** (`%APPDATA%\alaseel-pms`) ترفض الأداة التنفيذ
  وتطبع أمر الإرجاع الصحيح — لأن التطبيق يقرأ من مجلد userData فقط، والتصفير على نسخة
  في مكان آخر لن يظهر أثره.
- لتشغيل المهمة عبر جلسة Claude Code على اللابتوب نفسه، استخدم البريف الجاهز في
  `tools/HANDOFF-PROMPT.md`.
